# Mouse Sound FX — Python + HTML/CSS/JS

Тот же Mouse Sound FX, но вся логика — в чистом Python (`backend/`), а всё,
что видно на экране, — в HTML/CSS/JS (`web/`). Окно нативное, без браузера:
связывает их [pywebview](https://pywebview.flowrl.com/) — он открывает
системный веб-движок (WebView2 на Windows, WebKit на macOS, GTK-WebKit на
Linux) и пробрасывает Python-объект `Api` в JS как `window.pywebview.api`.
Окно безрамочное — своя шапка со свёрткой/закрытием и перетаскиванием за
логотип.

## Структура

```
main.py                  — точка входа: окно, проверка WebView2, связка с Api
backend/
  paths.py                — пути к ресурсам (с учётом PyInstaller)
  colors.py                — цветовая математика (blend/lighten/hsv/clamp)
  constants.py              — звуковые паки, пресеты темы, дефолтный конфиг
  config.py                  — чтение/запись config.json с валидацией
  sound_library.py            — загрузка и кэширование звуков (pygame)
  api.py                        — вся логика приложения и мост к JS
web/
  index.html                     — разметка
  style.css                       — вся визуальная часть и анимации
  app.js                            — вызовы api.*, перерисовка из состояния
```

`app.js` ничего не решает сам: читает, что нажал пользователь, зовёт
соответствующий метод `api.*`, перерисовывает экран из состояния, которое
вернул Python. Любая логика (валидация, конфиг, цвета) — в `backend/`.

## Установка

```
python -m pip install -r requirements.txt
```

Именно `python -m pip`, не голое `pip` — при нескольких Python в системе
(частый случай на Windows) голый `pip` может поставить пакеты не в то
окружение. Проверка: `python -c "import webview, pygame, pynput; print('OK')"`.

На Windows нужны два отдельных компонента современного интерфейса:
- **WebView2 Runtime** — системный компонент Windows, обычно уже стоит на
  10/11; если нет — [ставится тут](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)
  ("Evergreen Bootstrapper").
- **pythonnet** — Python-пакет, без него pywebview не достучится до
  WebView2, даже если тот стоит в системе. `requirements.txt` тянет его
  автоматически через `pywebview[winforms]`.

`main.py` сам проверяет оба компонента при старте и, если чего-то не
хватает, сразу показывает окно с понятной ошибкой вместо того, чтобы
открыть нерабочий интерфейс молча.

На Linux нужны системные пакеты GTK/WebKit. На macOS — работает из коробки.

## Перед первым запуском — перенесите свои звуки

Только сам код был загружен — самих звуковых файлов и вашего config.json
у меня не было. Скопируйте из старого проекта в корень нового (рядом с
`main.py`): `sounds/soft/`, `sounds/sharp/`, `sounds/deep/` (по 6 wav на
пак), `sounds/custom/` (если были свои звуки), `config.json` (если хотите
сохранить настройки). Без этого приложение всё равно запустится, но
встроенные паки играть не будут.

## Запуск

```
python main.py
```

Диагностика: `python main.py --debug`.

## Сборка в exe

Двойной клик по **`build.bat`** — сам поставит PyInstaller и соберёт всё
нужными флагами, с нуля каждый раз (сначала удаляет старые `build/` и
`dist/` — без этого PyInstaller может закэшировать старые файлы и
пересобрать exe, который выглядит новым, но внутри работает по-старому).

Вручную то же самое:

```
python -m pip install pyinstaller
python -m PyInstaller --clean --noconfirm --windowed --name "Mouse Sound FX" ^
  --add-data "web;web" --add-data "sounds;sounds" ^
  --collect-submodules webview --collect-submodules clr_loader --collect-submodules pythonnet ^
  --hidden-import pynput.mouse._win32 --hidden-import pynput.keyboard._win32 ^
  main.py
```

`--collect-submodules`/`--hidden-import` не косметика: pywebview и pynput
подгружают платформенный бэкенд динамически изнутри функций, а не обычным
`import` сверху файла — статический анализ PyInstaller такое не видит и
молча не берёт в сборку. Без этих флагов exe либо не запускается, либо
(коварнее) открывается, но не работает — без единой ошибки в консоли.

На Linux/macOS: `:` вместо `;` в `--add-data`, Windows-специфичные флаги
(`clr_loader`, `pythonnet`, `_win32`) не нужны.

Результат — папка `dist/Mouse Sound FX/`. **Для запуска и раздачи нужна
вся папка**, не один exe — рядом лежат обязательные DLL и ресурсы.

При первом запуске Windows покажет SmartScreen — это стандартная реакция
на новый неподписанный exe, не поломка ("Дополнительно" → "Выполнить в
любом случае").

## Если после моих правок ничего не поменялось

Три частые причины, по частоте:

1. **Собран старый кэш.** `build.bat` теперь чистит `build/`/`dist/` перед
   каждой сборкой сам — если у вас более старая копия скрипта, замените на
   актуальную из последнего ответа.
2. **Где-то запущен старый процесс.** Откройте Диспетчер задач, найдите
   "Mouse Sound FX" (может висеть в фоне, особенно если раньше зависал) —
   "Снять задачу", и только потом запускайте новую сборку.
3. **Файл заменён не в той папке или не полностью.** Каждый файл, который
   я присылаю, указывает, куда его класть (корень / `backend/` / `web/`) —
   стоит перепроверить путь и то, что сохранился именно новый файл, а не
   копия со старым содержимым под тем же именем.

## Окно без рамки: если будете трогать перетаскивание

Перетаскивание — за область логотипа слева (класс `pywebview-drag-region`
на ней); кнопки свернуть/закрыть — свои, справа, дёргают
`Api.minimize_window()`/`close_window()`.

Рабочая комбинация настроек — `easy_drag=True` в `create_window(...)`
ПЛЮС `webview.settings["DRAG_REGION_SELECTOR"] = ".pywebview-drag-region"`
до `create_window`/`start` (обе строчки уже в `main.py`). `easy_drag=False`
с этим же классом перетаскивание не запускает вообще — несмотря на то что
по названию можно было ожидать обратного (проверено эмпирически). Если
захочется сделать перетаскиваемой ещё какую-то область — добавьте тот же
класс нужному элементу, но не тому, что само по себе кликабельно (кнопки
внутри такой области тоже станут "тащить окно" вместо клика).

## Что изменилось по сравнению с оригиналом

Логика и поведение перенесены как есть (тот же конфиг, валидация,
алгоритм цветов, ограничение "не давать выбрать неоновый акцент") — но
раз рисовать теперь можно CSS, а не вручную считать точки на Canvas,
несколько мест стали проще без потери сути:

- Скругления мыши и кнопок — реальный CSS `border-radius`, не
  аппроксимация дугами через точки многоугольника.
- Анимации — CSS `transition`/`@keyframes`, не ручной покадровый
  пересчёт цвета в Python (подробнее — раздел ниже).
- Градиент выбора цвета — настоящий CSS-градиент, не 74 нарисованных
  вручную прямоугольника.
- Узор фона — SVG `<pattern>` одним слоем позади содержимого, с
  настоящей CSS-прозрачностью (`opacity`), не вручную подобранным «почти
  цвет фона». Вариантов семь: нет / соты / волны / ромб / точки / сетка /
  диагональные полосы.

Слой узора — `position: absolute`, а такие элементы браузер красит ПОСЛЕ
обычных block-элементов потока независимо от порядка в разметке (это
особенность стандарта CSS, не баг). Починено явным `z-index: -1` у слоя
узора и `z-index: 0` у `.stage`/`.panel` (чтобы стать контекстом
стекинга и не дать отрицательному z-index "убежать" ещё дальше назад).

## Анимации

Всё на чистом CSS — `app.js` только проставляет классы, а как это
выглядит, решают `@keyframes`/`transition` в `style.css`:

- Плашки интерфейса появляются по очереди при запуске (лёгкое затухание
  и сдвиг, у каждой свой `animation-delay`).
- Кнопка питания мягко пульсирует, пока звук включён.
- Выбор кнопки мыши / вкладки / цвета / узора — лёгкий "поп" масштабом,
  не мгновенная смена цвета.
- Большинство кнопок чуть проседают при нажатии — тактильный отклик.
- "▶" при клике даёт расходящееся кольцо поверх вспышки.
- Попапы, выпадающий список звука и модалки открываются с лёгким
  масштабированием.

Уважает системную настройку "уменьшить анимацию" (`prefers-reduced-motion`) —
все эффекты автоматически сжимаются почти до нуля, если она включена.
